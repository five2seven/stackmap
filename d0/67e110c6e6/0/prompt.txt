## 2. Fix blank imported path mappings

Current schema-version-3 imports accept a path mapping when:

- id is nonblank
- field types are valid
- hostPath is blank
- containerPath is blank
- purpose is blank

This conflicts with the normal editor behavior, which discards completely blank rows before storage.

Update current-version import validation so a path mapping is rejected when all three text fields are blank after trimming:

- hostPath
- containerPath
- purpose

Requirements:

- `readOnly` alone must not make an otherwise blank mapping valid.
- Whitespace-only values must count as blank.
- Partially completed mappings must remain valid.
- A mapping with only hostPath must remain valid.
- A mapping with only containerPath must remain valid.
- A mapping with only purpose must remain valid.
- Version 1 and version 2 migration behavior must remain unchanged.
- Do not mutate uploaded backup objects.
- Preserve exact-shape validation, duplicate path-ID checks, reference validation, and atomic replacement.

Use a clear import error message that identifies the invalid blank path mapping.

## 3. Add tests

Add focused tests covering:

- Schema-version-3 import rejects a path mapping with blank hostPath, containerPath, and purpose.
- Whitespace-only values are rejected.
- `readOnly: true` does not make an otherwise blank mapping valid.
- A hostPath-only mapping is accepted.
- A containerPath-only mapping is accepted.
- A purpose-only mapping is accepted.
- Existing schema-version-1 and schema-version-2 migration tests continue passing.
- Existing malformed-path and duplicate path-ID tests continue passing.
- Atomic replacement remains unchanged after rejection.
